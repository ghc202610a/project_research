# Documentation index

These documents describe intended direction, architecture, implementation boundaries, and exploratory work for maintainers, contributors, coding agents, and future planning.

- [Vision](VISION.md): problem space, principles, long-term intent.
- [Architecture](ARCHITECTURE.md): components, boundaries, data flow, deployment.
- [Data and knowledge model](DATA_MODEL.md): entities, assertions, provenance, temporal observations, semantic evolution.
- [Provider model](PROVIDERS.md): forges, Git, web, package indexes, external datasets.
- [Roadmap](ROADMAP.md): staged implementation direction.
- [Concepts to explore](CONCEPTS_TO_EXPLORE.md): research topics, not requirements.
- [PR1 scope](PR1_SCOPE.md): first implementation increment and exclusions.
- [Release tracker implementation](RELEASE_TRACKER.md): commands, storage, provenance, limits, and current limitations.
- [Agent guide](AGENT_GUIDE.md): contributor and coding-agent expectations.
- [Architecture decisions](adr/README.md): recorded decisions.

Status vocabulary: **Agreed direction** means accepted for planning; **Proposed** needs review; **Exploratory** is not a commitment; **Implemented** means present and verified; **Deferred** is outside the current increment. Roadmap items do not imply implementation.
