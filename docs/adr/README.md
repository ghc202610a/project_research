# Architecture decision records

ADRs capture decisions that materially constrain implementation. Keep them short, dated, scoped, and explicit about alternatives and consequences.

Status: **Accepted** (current direction), **Proposed** (under review), **Superseded** (replaced; retain history), **Deferred** (not decided).

## Index
- [0001 — Provider-neutral domain model](0001-provider-neutral-domain-model.md)

Create an ADR for decisions affecting provider boundaries, canonical identity, persistence, public interfaces, security, or interoperability—not every local implementation detail.
